# Active-span capture in a controlled sequential window

A bounded history can keep native batching and still distinguish nested active spans **when the application explicitly brackets every context change**. An omitted transition invalidates that promise. Ordinary SDK users cannot enable this probe transparently. A prepared-token queue also works at stopped drain points, at the expense of one callback and usually one distinct native log per entry. Neither experiment establishes a deployable low-cost integration.

## Results

At 1000 Hz and depth 256, history's paired median extra total CPU versus batching was +0.7% with two scope changes and +5.3% with 256. The seven-pair ranges were −15.5% to +191.7% and −9.9% to +9.7%. Work-only wall medians changed by +1.3% and +3.6%. History used one final callback per short worker, with median final flush near 67 ms in both cells. Its median linked share was 97.6% and 95.5% of event weight. Ambiguous observations cost coverage. The large outlier is retained. History round six in that cell collected 769 event weight and took 324 ms at final flush, compared with 317–329 weight and 64–73 ms in its other rounds. The cause is undetermined. These data do not establish a CPU ceiling.

Deferred parsing at the same depth and rate raised total CPU by +17.0% and +17.8% in the two churn settings. Work-only deltas were +16.5% and +13.2%. Median final flush was 77–78 ms and median RSS 46.5–48.4 MiB, versus 28.8–29.1 MiB for history. The one-entry logs retain their own deep stack data. Moving conversion to final flush does not eliminate native log creation. In the same cells the immediate/OTel control had work-only deltas of +29.0% and +34.9%, with much less work left at final flush. At depth 48 and 1000 Hz, history CPU medians were −0.7% and +2.6%, deferred +1.3% and +3.0%. At 100 Hz scatter prevents a dependable small-overhead estimate. [All medians, ranges, rates, memory and coverage](2026-11-23-otel-window/summary.md)

The history result supports an opt-in experiment for applications that already own all execution boundaries. No general-purpose cheap active-span option was demonstrated. A single UoW/root ID can avoid tracking child scopes at the cost of losing that distinction. A lower timer rate reduces temporal resolution. Neither substitution implements the measured active-span semantics.

## Evidence and semantics

The [previous experiment](2026-11-17-otel-callback-preflight.md) used four modes and one stable SDK span. Recomputing the paired CPU medians from its 112 rows gives +7.69% and +8.42% at 1000 Hz. Benchmarks [#3](https://github.com/tracewick/benchmarks/pull/3) retained that evidence. Core [#81](https://github.com/tracewick/tracewick/pull/81) was withdrawn. Core [#84](https://github.com/tracewick/tracewick/pull/84) fixed a separate callback bootstrap problem. The new controls use those published sampler paths on the RC checkout.

- **History.** Bracket construction of the native profiler with Linux monotonic hrtime reads. Excimer takes its epoch inside construction, timestamps entries when the VM handles the interrupt, and copies log options across flushes. Add the relative entry time to both construction bounds, allowing 1 ns for rounding. Binary-search the last interval starting before the earliest possible observation. Attribute only if its end exceeds the latest possible observation. Close the interval before touching the SDK scope and open the next after reading the restored context. A full 512-interval history discards its old block. Entries from discarded intervals retain their stack and weight with no IDs. This clock argument applies to the tested Linux build. [Excimer 1.2.7 source](https://github.com/wikimedia/mediawiki-php-excimer/blob/1.2.7/excimer.c)
- **Deferred.** Invalidate the prepared token before each change and publish the new valid local ID pair afterward. Save each single-entry native log with that token. Retain at most 512 logs. On saturation, ingest the new log immediately without IDs. Memory still depends on stack depth and native allocation. A first drain-while-running trial failed conservation because callbacks appended during queue processing. All reported rotations stop sampling before draining, then restart. Work in that gap has no samples. The historical automatic UoW listener is outside this prototype.
- Both paths join **before** the core trace converter ingests the stack into a per-token aggregator. Admission allows 15 ID pairs plus one uncorrelated group per drain, each capped at 512 stacks with core frame/string limits. IDs identify the active valid local span, including unsampled and ended-but-still-active spans. No span, remote-only context, and every entry with event count greater than one retain all their weight without IDs. A coalesced entry has one observation time. It cannot resolve individual ticks inside a C call.
- Eligibility is supplied by the harness before sampling. Windows with unknown storage, incomplete bootstrap, or possible unobserved execution switches must run entirely uncorrelated. The pinned SDK exposes attach and detachable scopes. Its default Fiber storage selects a head by the current Fiber, so instrumenting attach/detach alone misses suspend/resume. Custom storage can implement different semantics. A transparent decorator would need early installation, scope identity/restoration, execution-context forwarding, compatibility with later storage replacement and a way to observe switches. The experiment assumes none of those capabilities in arbitrary PHP applications.

## Correctness

Each of the two candidates ran three marked-stack probes with a real SDK and Excimer. Each probe runs two sequential logical units on one sampler, with an explicit stopped rotation mid-unit and an empty repeat flush at the end. The oracle checks no context, remote parent, local child, nested and restored spans, reactivation of an ended child, unsampled local span, and a blocking sleep. The ineligible-window case also enters a Fiber with an active parent on the main stack. A four-slot limit forces eviction or queue overflow. The oracle compares raw log event counts with final aggregate weight and checks that marked entries carrying IDs match the phase. It requires actual linked observations in each eligible local phase under the normal bound. Test-only phase expectations stay outside the measured workers. The deliberately incorrect late lookup must produce mismatches. [Raw checks](2026-11-23-otel-window/correctness.json)

This covers explicit rotations in the probe. Automatic core rotation, spool writes, disk duplication, process forks, custom storage faults and concurrent drains are unverified for the new candidates. The experiment has no sink, spool or network delivery. The earlier disk checks exercised a different callback path.

## Other implementations inspected

- Grafana sets and restores goroutine pprof labels and defaults to root-span ID scope. All-spans is a different option. PHP Excimer exposes no corresponding runtime label attached to a native entry. [Go implementation](https://github.com/grafana/otel-profiling-go/blob/4559e398e4aa58f37c7f32ee7d9b09f1ac2054fe/otelpyroscope.go)
- Sentry converts Excimer entry timestamps and emits profile chunks carrying profiler ID and thread/time coordinates. A request-level timeline link can be valuable for navigation. It cannot by itself identify the active span under detach/reactivation. [Chunk implementation](https://github.com/getsentry/sentry-php/blob/67114a7b169415fe583b9e49811cba4be9083bfa/src/Profiling/ProfileChunk.php)
- Datadog's Rust profiler reads span and local-root IDs through native tracer integration. A PHP/Excimer equivalent needs an ID publisher synchronized with execution switches and a native sampling hook, adding build, ABI, deployment and compatibility work. [Native reader](https://github.com/DataDog/dd-trace-php/blob/144f03a0abf37aabb1c7cd68eb40c7811b8a4d2a/profiling/src/profiler/mod.rs)
- The OTel eBPF profiler checks for a published TLS buffer and skips absent or mid-update state. A compatible publisher and host profiler would be additional requirements. [Thread context reader](https://github.com/open-telemetry/opentelemetry-ebpf-profiler/blob/50edbb45c361118cc9d2be66a955411f3f52dc57/support/ebpf/interpreter_dispatcher.ebpf.c)
- PHP OTLP exporters serialize and send already collected signals. Capture remains upstream of that boundary. [OTLP sources](https://github.com/open-telemetry/opentelemetry-php/tree/f0667f79d79d911ba9bfe69d0f8a0730b53eb7bb/src/Contrib/Otlp)
- Excimetry's **exporter** addMetadata returns itself without storing IDs. Its JSON stack-derived spans lack traceId/spanId and its protobuf path builds a metrics request while the backend targets /v1/traces. Other classes do store metadata. [Exporter](https://github.com/excimetry/excimetry/blob/89180e8212a1270a5be2a6cf9687160eaeae363f/src/excimetry/Exporter/OTLPExporter.php) · [Backend](https://github.com/excimetry/excimetry/blob/89180e8212a1270a5be2a6cf9687160eaeae363f/src/excimetry/Backend/OTLPBackend.php)

## Reproduction

Use sibling core and benchmarks checkouts at the revisions above. Install core development dependencies and run composer install in experiments/otel-callback using its existing lock. Run in benchmarks with the stated PHP and extension versions. The targets below are fresh output paths.

```sh
php -d pcov.enabled=0 experiments/otel-window/correctness.php > /tmp/correctness.json
php -d pcov.enabled=0 experiments/otel-window/run.php > /tmp/rows.jsonl
python3 experiments/otel-window/summarize.py /tmp/rows.jsonl
```

For callback I/O, run io.php with the mode history or deferred under strace using the same file, network, read, write and close filter and marker parser as the historical experiment. The history threshold of eight and queue bound of four exercise automatic callback ingestion and saturation. The measured probes initialize dependencies before starting. Marker writes are excluded.
